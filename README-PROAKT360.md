# ПрорАКТ 360 — кабинет строителя

Индивидуальное приложение для строителя-маляра: **прайс → смета → еженедельные акты без перепечатывания → оплаты → кабинет клиента**, без Google Sheets. Развитие демо-прототипа на базе идей открытого репозитория [proakt-build-bot](https://github.com/Sereban-glitch/proakt-build-bot) (использованы домен и UX-находки; код переписан с нуля под веб).

> **Демо-режим.** Все данные после сида — вымышленные (имена, адреса, цены помечены `source: demo`). Реальные прайсы и документы в приложение не зашиты; их можно импортировать локально (см. «Импорт реального прайса»).

---

## Быстрый запуск (Node.js + npm — БЕЗ Bun)

```bash
npm install
cp .env.example .env          # DATABASE_URL (можно не менять)
npx prisma db push            # схема SQLite + генерация клиента
npm run db:seed:node          # демо-данные: 3 объекта, сметы, акты, фото
npm run dev                   # http://localhost:3000
```

Вариант на Bun (если установлен): `bun install && bun run db:push && bun run db:seed && bun run dev`.

**DATABASE_URL** — путь к файлу SQLite. Нюанс Prisma: **относительные** пути
резолвятся от каталога `prisma/`, поэтому дефолт в `.env.example` —
`file:../db/custom.db` (файл ляжет в `db/custom.db`, фото — в `db/uploads/`).
Абсолютный путь работает как есть: `file:/home/user/proakt.db`. Внешних баз и
серверов не требуется. База и папка фото всегда рядом (переносятся копированием
одного каталога `db/`).

## Первоначальная настройка владельца (ВАЖНО)

Свежая установка **закрыта по умолчанию** (fail-closed): пока не задан пароль мастера,
все мастерские API отвечают `503`, а веб показывает экран «Требуется первоначальная
настройка». Задать пароль удалённо нельзя — только с машины, где лежит база:

```bash
npm run setup:password              # интерактивно, ввод скрыт
npm run setup:password -- --stdin   # пароль из stdin (скрипты)
npm run setup:password -- --reset    # смена уже заданного пароля
```

После этого вход в веб — экран «Вход мастера» → пароль → сессия на 30 дней.
Смена пароля аннулирует все сессии.

**Локальное демо без пароля** — только осознанным решением, добавьте в `.env`:

```
PROAKT_DEMO_OPEN=1
```

Тогда мастерские экраны открыты, пока пароль не задан. Экземпляр с флагом не считайте
production: закройте его от интернета или задайте пароль.

## Production-запуск (Node.js)

```bash
npm run build      # next build (проверка типов включена)
npm run start      # next start -p 3000 (NODE_ENV=production)
```

- Перед `build`/`start` выполните первичную настройку (пароль) — иначе приложение
  будет отвечать экраном настройки и `503` на мастерских API.
- Запускайте за HTTPS-прокси (Caddy/nginx). Cookie сессии автоматически получает
  флаг `Secure`, когда прокси передаёт `x-forwarded-proto: https`
  (или задайте `PROAKT_FORCE_SECURE_COOKIES=1`).
- Вход защищён ограничением попыток: 5 неверных паролей с одного IP за 15 минут →
  `429` (счётчик в памяти процесса, см. «Границы»).
- Изменение состояния (POST/PUT/PATCH/DELETE) мастерских API проверяет `Origin` —
  межсайтовые запросы отклоняются (`403`) в дополнение к `SameSite=Lax` cookie.

## Резервное копирование и восстановление

- **Данные**: «Настройки» → «Скачать бэкап (JSON)» — все таблицы.
- **Фото**: файлы лежат в `db/uploads/` и в бэкап не входят — копируйте папку целиком.
- **Восстановление**: «Настройки» → «Восстановить из файла» — замещает все данные
  (сессии сохраняются). Папку `db/uploads/` верните копированием.
- Автотест восстановления на синтетической базе:

```bash
DATABASE_URL="file:/tmp/synth.db" npx prisma db push --skip-generate
DATABASE_URL="file:/tmp/synth.db" npm run test:restore
```

## Демо-данные: безопасный сид

- `npm run db:seed:node` работает **только с пустой базой**; в непустой — отказ,
  ничего не удаляется.
- Сброс демо-данных (с автоматическим бэкапом `db/*.backup-before-seed-*` и
  копией `db/uploads`):

```bash
npm run db:seed:reset
```

## Изолированный e2e-тест (после сборки)

Проверяет целиком безопасность и рабочий процесс на одноразовой temp-базе:
fail-closed ненастроенного production, демо-режим, вход с rate limit и Secure
cookie, origin-защиту, полный цикл «объект → смета → частичный недельный акт →
запрет превышения остатка (409) → оплата», изоляцию клиентов, фото с видимостью
и сохранностью после перезапуска, бэкап/восстановление, RU/UK документы, logout:

```bash
npm run build
npm run test:e2e
```

Рабочая база не затрагивается (скрипт создаёт базу во временной папке и сам её удаляет).

## Безопасность и приватность

- **Пароль мастера** хешируется **scrypt** (N=16384, r=8, p=1, 64 байта, случайная
  соль; Node.js `crypto`). Пароли старой версии (sha256) принимаются и прозрачно
  апгрейдятся при первом входе. Сессия — HttpOnly cookie, 30 дней, `SameSite=Lax`;
  `Secure` включается автоматически при HTTPS (см. выше).
- **Fail-closed**: без пароля и без `PROAKT_DEMO_OPEN=1` мастерские API закрыты
  (`503`), удалённая настройка невозможна. Захват «первоначальной настройки»
  извне исключён: пароль задаётся только локальным CLI.
- **Rate limit входа**: 5 попыток / 15 минут с одного IP → `429 Retry-After`.
- **Origin-проверка** всех изменений состояния мастерских API.
- **Клиентские ссылки** — токены: объект/смета/акт. Любой из трёх открывает кабинет
  одного конкретного объекта; чужие данные, фото и согласования недоступны (проверено
  автотестом: `403` на чужой токен).
- **Фото** хранятся в `db/uploads/` ВНЕ `public/` — отдаются только через API:
  мастер — сессией, клиент — токеном и только фото с «видно клиенту».
- Внешние сервисы, OAuth и API-ключи не используются. Секретов в `.env.example` нет.

## Импорт реального прайса (локально)

Каталог принимает JSON вида:

```json
{ "items": [ { "name": "шпаклёвка стен под стеклохолст", "unit": "м²",
               "price": 120, "section": "стены",
               "source": "прайс 2026-10", "sourceDate": "2026-10-18", "note": "" } ] }
```

«Настройки» → «Импорт каталога» → выберите файл → режим «Обновить и добавить»
(или «Заменить весь каталог»). Источник и дата сохраняются у каждой позиции — при
конфликте версий видно, откуда цена.

## Стек и структура

- **Next.js 16 (App Router) + TypeScript**, Tailwind CSS 4, shadcn/ui, TanStack Query, framer-motion, zustand.
- **Prisma + SQLite** (`prisma/schema.prisma`): объекты, этапы, сметы + строки (разделы, doneQty), акты + строки, оплаты, фото (файлы + миниатюры sharp), прайс с источниками, шаблоны, комментарии, сессии.
- **API** — `src/app/api/**` (REST, JSON): аутентификация (`/api/auth/*`), настройки, объекты/сметы/акты/оплаты/прайс/шаблоны, загрузка фото (`multipart`), экспорт XLSX (SheetJS) и текста акта, бэкап/восстановление, кабинет клиента по токену.
- **Фронтенд** — одностраничное приложение на `/` с hash-навигацией: `src/components/app.tsx` (гейт: настройка → вход → приложение), `src/views/*` (экраны), `src/lib/i18n.ts` (RU/UK).
- Скрипты: `scripts/set-password.ts` (первичная настройка), `scripts/test-restore.ts` (автотест восстановления), `scripts/e2e-check.ts` (изолированный e2e).

## Границы текущей версии (честно)

- Однопользовательский кабинет мастера; rate limit и сессии — в памяти одного
  процесса (перезапуск сбрасывает счётчик попыток; SQLite предполагает один
  инстанс — горизонтальное масштабирование не поддерживается).
- Это изолированная копия для развития; **рабочий Telegram-бот, сервер и БД оригинала не тронуты**.
- Нет интеграции с Telegram API (текст акта копируется в чат вручную), нет голосового ввода, нет онлайн-оплат.
- Экспорт XLSX — упрощённый формат в духе рабочих файлов (одна строка «Загальна сума»), без фирменных шапок.
- Акты создаются из строк сметы; строки «вне сметы» можно внести только сидом/напрямую в БД (в UI редактора таких строк нет).
- Скрипт `db:seed` (Bun-вариант) и `db:seed:node` (tsx) эквивалентны; на чистом npm используйте `db:seed:node`.
- Формат бэкапа v2 не совместим с данными первой версии прототипа.
- e2e-тест и восстановление проверены на синтетике; **smoke-тесты не заменяют
  эксплуатационную проверку на реальных данных владельца**.

## Источники UX

Изучены публичные материалы: Buildertrend (кабинет клиента как первоклассный опыт), Houzz Pro (смета как презентационный документ + согласование клиентом), Procore (фото-документация этапов). Взяты принципы, не код и не бренды. Персональные материалы владельца использованы только для анализа процесса (в репозиторий и демо не входят).
