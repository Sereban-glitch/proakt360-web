# ProAkt 360 — веб-прототип V2

На GitHub опубликован ZIP-снимок исходников `proakt360-public-prepared.zip` и эта памятка. Распакуйте архив в отдельный каталог: структура и команды ниже относятся к его содержимому. Это не развёрнутое приложение.

Отдельный веб-прототип для строительных работ: объекты → сметы → недельные акты → оплаты → кабинет клиента. Интерфейс RU/UK, прайс, шаблоны, помещения, фотоотчёты и экспорт.

**Статус: рабочая демо-версия V2 для дальнейшей разработки, не готова к production.** Это подготовленная копия исходников V2; исправленная сборка ещё ожидается и сюда не включена. После очистки демо-данных эта копия не запускалась: успешная сборка и регрессионные тесты не заявляются.

## Что лежит в репозитории

- `src/`: интерфейс Next.js, API, обработка данных и синтетический сид.
- `prisma/schema.prisma`: схема SQLite.
- `package.json`, `bun.lock`, конфигурация TypeScript, Next.js и CSS.
- `.env.example`: только пример локального пути SQLite.

Реальных документов, переписок, клиентских файлов, фотографий, баз данных, резервных копий и секретов здесь нет. Названия клиентов, объектов, адреса и комментарии заменены явно демонстрационными. Все ставки в сиде намеренно равны **10 условным единицам** и не являются прайсом. Фото генерируются программно. Публичные `demo-*` ссылки предназначены исключительно для синтетического сида.

Это отдельная линия разработки; исходный [proakt-build-bot](https://github.com/Sereban-glitch/proakt-build-bot) не изменяется этой копией. Файл лицензии не добавлен: лицензирование и происхождение компонентов нужно проверить отдельно; публичная доступность сама по себе не предоставляет лицензию.

## Локальная проверка

Используйте только новый пустой каталог и одноразовую SQLite-базу. Не подключайте реальные данные и не открывайте сервер в интернет.

```sh
bun install
cp .env.example .env
bunx prisma generate
bunx prisma db push
bun run db:seed
bunx next dev --hostname 127.0.0.1 -p 3000
```

Перед командами проверьте `DATABASE_URL`: относительный SQLite-путь Prisma разрешает относительно файла схемы. Каталог файлов фото определяется отдельно: `db/uploads/` от рабочего каталога приложения.

**Внимание:** `db:seed` удаляет существующие записи, настройки и сессии, а также каталог `db/uploads/`. Скрипт `db:push` в `package.json` содержит `--accept-data-loss`; для проверки выше показана команда без этого флага. Не запускайте seed/reset/restore на рабочей базе.

Для Node.js доступны `npm install`, `npx prisma generate`, `npx prisma db push`, `npm run db:seed:node`, `npx next dev --hostname 127.0.0.1 -p 3000`. Полная совместимость не проверена; production-скрипт `start` всё ещё требует Bun.

## Известные блокеры и честные ограничения

1. **Fail-open аутентификация:** без заданного пароля сервер считает мастера авторизованным. Это не безопасная первая настройка для публичного сервера.
2. Пароль хешируется быстрым SHA-256 с солью. Требуется специализированный password KDF и проверка всей модели сессий/доступа.
3. В архиве нет `public/`, но `build` выполняет `cp -r public`; также есть ссылка на отсутствующий `/logo.svg`. Сборку и ресурсы нужно исправить и проверить.
4. `next.config.ts` игнорирует ошибки TypeScript при сборке. Нужны отдельная строгая проверка типов, lint и исправление найденных проблем.
5. В архиве нет заявленного ранее `scripts/test-restore.ts`. Восстановление не подтверждено воспроизводимым тестом. JSON-бэкап не включает файлы фото; восстановление заменяет данные.
6. `start` зависит от Bun. Надо выбрать и проверить поддерживаемый runtime для build/start.
7. Сид разрушительный, а известные демо-токены общедоступны. Требуются защита от случайного запуска на рабочей базе и тесты доступа между объектами, фото, комментариями и согласованиями.
8. Нет интеграции Telegram API, голосового ввода и онлайн-оплат. UI для произвольных строк акта вне сметы отсутствует. Формат бэкапа V2 не заявлен совместимым с V1.
